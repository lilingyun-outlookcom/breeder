# 动物/繁育/诊疗/库存/记录查询 功能优化方案（修订版 v2）

## 一、设计分析（v2 修正）

### 1. 动物表改为「物种/类型」级
用户明确：`animals` 表**本身**从个体表改为物种表，每行 = 一类动物，带「总数量」字段；特殊动物仍可当个体使用（数量=1）。

- 鸟类 → 一行「孔雀，total=50」；明星个体 → 一行「小虎，total=1，带名字/照片/性别」。
- 总数量 = **存储值**（`total`），不再用 COUNT 个体数。
- 繁育/诊疗/任务/异常上报都引用 animal_id，链路天然兼容。

### 2. 诊疗支持群体（本次新增）
- 一个诊疗计划可同时覆盖**同一物种行的多只动物**（录入「诊疗数量」），不同物种**分开建计划**。
- 待产数/生病数口径：
  - **生病数** = 该动物行所有进行中诊疗计划的 `quantity` 之和（正在诊疗的只数，含个体=1）。
  - **待产数** = 该动物行进行中「妊娠」繁育计划数。
- **确认死亡按只数扣减**：输入死亡只数 → `animals.total -= 死亡只数`，同时诊疗计划剩余数量同步减少；计划剩余数量减到 0 则计划结束；动物行 total 减到 0 则自动下架（status=0）。

### 3. 数量增减来源
- 繁育：分娩登记 `alive_count` → `animals.total += 存活数`（完成繁育后可新增数量）。
- 诊疗：确认死亡 `died_count` → `animals.total -= 死亡只数`（生病数据里确定死亡的减去只数）。
- 动物编辑表单也可直接修改「总数量」（兜底）。

## 二、数据库变更（`schema.sql` + `db.ts` 幂等迁移）

1. `animals` 加列：`total INT NOT NULL DEFAULT 1`（总数量；存量行自动=1）。
2. `feeds` 加列：`stock DECIMAL(12,2) NOT NULL DEFAULT 0`（库存）。
3. `medicines` 加列：`stock DECIMAL(12,2) NOT NULL DEFAULT 0`（库存）。
4. `treatment_plans` 加列：`quantity INT NOT NULL DEFAULT 1`（本次诊疗覆盖只数，默认 1=个体）。
5. `medication_records` 加列：`quantity DECIMAL(10,2) NULL`（本次用药数值，用于扣库存；dosage 文本保留）。
6. 新建表 `inventory_records`（饲料/药品出入库流水）：
   ```sql
   CREATE TABLE IF NOT EXISTS inventory_records (
     id INT AUTO_INCREMENT PRIMARY KEY,
     item_type ENUM('feed','medicine') NOT NULL,
     item_id INT NOT NULL,
     change_type ENUM('buy','loss') NOT NULL,   -- 买入/灭失
     quantity DECIMAL(12,2) NOT NULL,
     remark VARCHAR(255) DEFAULT '',
     created_by INT NULL,
     created_at DATETIME,
     KEY idx_item (item_type, item_id)
   ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
   ```
7. `db.ts` 的 `initSchema()` 增加幂等迁移 `ensureColumn(table, column, ddl)`：查 `information_schema.columns`，缺列则 `ALTER TABLE ... ADD COLUMN`（兼容线上老表）。

## 三、后端接口变更

### 1. `routes/records.ts`
- **BUG 修复**：各记录类型 `listJoin` 关联字段全部加别名：
  `c.name AS cage_name, a.name AS animal_name, f.name AS feed_name, m.name AS medicine_name, u.name AS user_name`
  （根因：原无别名，`name` 重复列被 mysql2 后值覆盖，前端取 `cage_name/animal_name/feed_name` 全为空）。
- **喂食扣饲料库存**：POST `/records/feeding` 后 `UPDATE feeds SET stock=stock-?`，库存不足拒绝提交。
- **用药扣药品库存**：POST `/records/medication` 校验数字字段 `quantity`（本次用药数量），扣减 `medicines.stock`，不足拒绝。
- **繁育分娩登记**：POST `/records/breeding` 且 `record_type='分娩登记'` 时：
  - `UPDATE animals SET total=total+alive_count WHERE id=母兽id`；
  - 繁育计划 `status='done'`（自动完成）；计划下剩余未完成繁育任务置 done 并同步 task_groups。

### 2. `routes/tickets.ts`（诊疗计划）
- POST `/treatment-plans`：接受 `quantity`（默认 1），校验 `1 ≤ quantity ≤ animals.total`。
- PUT `/treatment-plans/:id`：允许修改 `quantity`（同校验）。
- **新增** POST `/treatment-plans/:id/death`（admin/vet），body `{died_count}`：
  - 校验 `1 ≤ died_count ≤ 计划剩余quantity`；
  - `UPDATE animals SET total=GREATEST(total-?,0)`（total 变 0 则 status=0 下架）；
  - `UPDATE treatment_plans SET quantity=GREATEST(quantity-?,0)`（变 0 则 status='done'）；
  - remark 追加「确认死亡 N 只」。

### 3. `routes/admin.ts`
- `GET /animals`：列表 SQL 附两个动态列：
  ```sql
  (SELECT COALESCE(SUM(tp.quantity),0) FROM treatment_plans tp
     WHERE tp.animal_id=a.id AND tp.status='active') AS sick_count,
  (SELECT COUNT(*) FROM breeding_plans bp
     WHERE bp.female_animal_id=a.id AND bp.status='active' AND bp.plan_type='妊娠') AS pregnant_count
  ```
- **新增** `POST /animals/merge`（admin）：合并「同物种+同笼舍+同饲养员」的多行：
  - 目标行 = 最小 id 行；`total=Σtotal`；
  - 重映射引用：tasks/feeding_records/treatment_plans/breeding_plans(female/male)/abnormal_reports/cub_records 的 animal_id 旧行 → 目标行；
  - 其余行 status=0（下架）。返回合并行数。
- **新增** `POST /inventory`（admin/vet）：`{item_type:'feed'|'medicine', item_id, change_type:'buy'|'loss', quantity, remark}`：
  - buy：`stock+=quantity`；loss：`stock-=quantity`（不足拒绝）；写入 `inventory_records`。
- **新增** `GET /inventory-records`：`?item_type=feed|medicine&date=`，JOIN 返回 `item_name/item_type/change_type/quantity/remark/user_name/created_at`。
- 看板 `GET /stats/dashboard`：`animalCount` 改为 `SELECT COALESCE(SUM(total),0) FROM animals WHERE status=1`（在册动物数 = 各类型总数量之和）。
- `routes/keeper.ts` 首页 `animalCount`（负责动物）同步改为 `SUM(total)`。

## 四、前端页面变更

1. **`admin/Animals.vue`（动物管理）**：
   - 表格新增列：总数量(total)、待产数(pregnant_count)、生病数(sick_count)；
   - 新增/编辑表单加「总数量」输入（默认 1）；
   - 页头加「合并同类」按钮（confirm 后调 POST /animals/merge，提示合并了 N 类）。

2. **`admin/Treatment.vue`（诊疗计划）**：
   - 录入/编辑表单加「诊疗数量」输入（默认 1，提示不可超过该动物总数量）；
   - 列表加「数量」列；
   - 进行中计划操作列加红色「确认死亡」→ 弹窗输入「死亡只数」（默认=剩余在诊数）→ 调 POST /treatment-plans/:id/death。

3. **`admin/Reports.vue`（异常工单→录入诊疗方案）**：方案弹窗加「诊疗数量」输入。

4. **`admin/Breeding.vue`（繁育计划）**：记录弹窗展示分娩自动加数说明；「结束」逻辑不变。

5. **`admin/Medicines.vue` / `admin/Feeds.vue`（药品/饲料管理）**：加「总数(stock)」列；操作列加「买入」「灭失」按钮 → 弹窗输入数量+备注 → 调 POST /inventory。

6. **`admin/Records.vue`（记录查询）**：新增「饲料出入库」「药品出入库」标签 → GET /inventory-records；原有各记录类型随 BUG 修复恢复正常显示。

7. **`keeper/TaskDetail.vue`（饲养员）**：用药表单加「本次用药数量」数字必填（用于扣药品库存）；喂食已有数量字段不变。

8. **`keeper/Animals.vue`（我的动物）**：列表加「总数量」列。

9. **首页看板 `admin/Dashboard.vue`**：显示逻辑不变，后端口径已改（在册动物数=各类型总数量之和），回归验证即可。

## 五、部署步骤（按 AGENTS.md 默认部署 PROD + 构建 dev）

1. 前端：`cd dev/frontend && npm run build:dev && npm run build:prod`，`rsync -av --delete dist-prod/ /opt/breeder/prod/backend/public/`。
2. 后端：`cd dev/backend && npm run build`，按 `scripts/deploy.sh` 同步到 `prod/backend`（无新 npm 依赖）。
3. 重启：`systemctl restart breeder-dev` 与 `systemctl restart breeder-prod`（启动时自动执行 DB 幂等迁移）。
4. 验证：health、`/api/animals`（含新列）、`/api/inventory-records` 正常，前端 bundle 为最新。
